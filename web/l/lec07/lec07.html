Q&A. Error patterns

  1. Not using the lib: e.g., own gen_range() for RdRand
  2. Circular dependency: e.g., using impls::next_u32_via_fill() in next_u32()
  3. Lack of entropy: e.g., RNG_DATA.read_volatile() as u64 in next_u64()

Freestanding binary

  • Taking control over exactly what we want/need
    • Dropping standard library
    • Accessing underlying hardware/machine code (i.e., assembly)
    • Often, targeted to run on a baremetal machine (i.e., no OS)

Freestanding C

  • About C runtime/startup (/lib/crt*.so)
  • About linker/entry point (ld)
  • About inline assembly (asm)
// gcc -nostdlib freestanding.c
void _start() {
  asm volatile ("mov $1, %%rdi\n"
                "mov $0x3c, %%rax\n"
                "syscall"
                :
                :
                :"rax", "rdi");
}

Freestanding Rust

  • A bit heavy lifting required for Rust, but certainly doable (see later)
    • About no_std / no_main
    • About panic_handler / lang_items
#[no_mangle]
fn _start() {
    unsafe {
        asm!("mov rdi, $$1
              mov rax, $$0x3c
              syscall"
             :
             :
             :"rax"
             :"volatile", "intel");
    }

About libcore, liballoc, libstd

  • libcore: dependency-free foundation (i.e., no libc, no heap)
    • Requires panic and eh_personality
  • liballoc: smart pointers and heap-managed collections (i.e., Box)
    • Requires global_allocator and alloc_error_handler
  • libstd: a set of shared abstractions for Rust software (e.g., I/O, networking, thread)
    • Depending on libcore and liballoc

About libcore, liballoc, libstd in OS development

  • libcore: our OS code, in particular early code, only relies on core (from lab1)
  • liballoc: once we have a managed heap on physical pages (from lab3)
  • libstd: not allowed! but partly import what we’d like (e.g., Path from lab3)

no_std

  • No default prelude and std libraries used/linked
// extern crate std;
// use std::prelude::v1::*;

#![no_std]

fn plus_one(x: i32) -> i32 {
    x + 1
}

Ref. No stdlib, Rustbook

no_main

  • No fn main() defined (i.e., explicitly defining an entry point)
  • Linker’s default entry point is _start()
#![no_main]

#[no_mangle]
pub extern fn _start() -> ! {
  // your program
}

panic_handler
